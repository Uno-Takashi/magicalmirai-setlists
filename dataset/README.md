# dataset

マジカルミライのセットリストデータ。**このディレクトリがデータの正 (source of truth)** で、
アプリはここの YAML をビルド時に読み込む。コードを触らずにこの中だけを編集すれば更新できる。

## 構成

```
dataset/
  vocaloids.yaml     ボーカロイド6人のマスタ (ID・名前・テーマカラー)
  songs.yaml         楽曲マスタ (全年度で共有)
  2013/
    edition.yaml     開催回のメタ情報 (公演地・会場・日程)
    setlist.yaml     セットリスト
    title.png        タイトル画像 (任意)
  2014/
  ...
```

## 検証

編集したら次を実行する。**ブラウザを立ち上げないので 1 秒ほどで終わる。**

```bash
pnpm test:dataset
```

CI (`.github/workflows/ci.yml`) でも同じものが走る。中身は
`src/infrastructure/dataset/dataset.node.test.ts` で、3 段階を見ている。

1. **YAML として読めるか。** キーの重複やインデントの崩れをここで落とす。
2. **構造がスキーマに合うか。** `src/infrastructure/dataset/datasetSchema.ts` の
   Zod スキーマと突き合わせる。**書いていないキーは受け付けない**ので、
   `youtub:` のような綴り違いは「黙って無視」ではなくエラーになる。
   `region` / `session` / `tags` の値、日付の形式、YouTube の動画 ID が
   11 文字であることもここで見る。
3. **ファイルをまたいだ参照が解決するか。** セットリストの曲名が `songs.yaml` に
   あるか、`singers` が `vocaloids.yaml` にあるか、`shows` が指す公演回が
   `edition.yaml` にあるか、年ディレクトリ名と `year` が一致しているか。

**`pnpm build` はこれを見ない。** dataset の YAML は文字列としてバンドルされ、
解釈はブラウザで初めて起きる。壊れていてもビルドは通り、配信してから真っ白になる
(実際に起きた: [#46](https://github.com/Uno-Takashi/magicalmirai-setlists/pull/46))。
データを触ったら必ず `pnpm test:dataset` を通すこと。

**項目を増やすときは `datasetSchema.ts` に足す。** 足さないと未知のキーとして弾かれる。
`src/infrastructure/dataset/rawTypes.ts` の型はスキーマから導いているので、
型を別に書き足す必要はない。

## タイトル画像

`dataset/<年>/title.png` を置くと、その年のページの上部に左右中央揃えで表示される。
`.png` / `.jpg` / `.webp` / `.svg` に対応し、**YAML もコードも触る必要はない**。
置いていない年は、これまでどおり開催回名の見出しが出る。

代替テキストには開催回名が入るので、画像に文字が含まれていても読み上げは成立する。
画像がある年は見出しを読み上げ専用にして、同じ文字が二重に出ないようにしている。

> **権利に注意。** 公式サイトのロゴやキービジュアルは主催者の著作物で、ピアプロ・
> キャラクター・ライセンスの対象外 (ロゴマークは同ライセンスで明示的に除外されている)。
> 公開サイトに置く画像は、利用条件を確認したものだけにすること。

## 新しい年を追加する

1. `dataset/<年>/` を作る (10th のように通称がある年もディレクトリ名は西暦にする)
2. `edition.yaml` と `setlist.yaml` を既存年からコピーして書き換える
3. 新しく登場した曲を `songs.yaml` に追加する
4. `pnpm dev` で表示を確認する

`setlist.yaml` から `songs.yaml` に無い曲を参照するとアプリの起動時にエラーになる。
タイプミスはここで気づける。

## edition.yaml

```yaml
year: 2023
slug: '2023' # URL に使う識別子。10周年の年は '10th' のように西暦と変えられる
name:
  ja: 初音ミク「マジカルミライ 2023」
  en: 'Hatsune Miku "Magical Mirai 2023"'
officialUrl: https://magicalmirai.com/2023/ # その年の公式サイト (省略可)
background: prism # 背景アニメーションの ID (src/presentation/backgrounds)
performances:
  - id: osaka
    region: osaka # tokyo | osaka | other — 公演地のテーマカラーを決める
    city:
      ja: 大阪
      en: Osaka
    venue: # 未確定なら省略してよい
      ja: インテックス大阪
      en: INTEX Osaka
    halls: # 会場内で使った施設。公式サイトの表記のまま (省略可)
      ja: 3号館・4号館・5号館A
      en: Halls 3, 4 and 5A
    mapQuery: インテックス大阪 # 地図の検索語。省略時は venue.ja を使う (省略可)
    shows:
      - id: day1
        date: 2023-08-11 # YYYY-MM-DD
        label: Day.1
        session: matinee # matinee | evening | 省略(昼夜の区別なし)
```

`name` / `city` / `venue` は言語ごとに書ける (`ja` は必須)。指定の無い言語は `ja` に
フォールバックするので、`zh-Hant` や `ko` を足したい場合はキーを増やせばよい。

`officialUrl` は省略できる。省略した場合、画面にリンクは出ない。URL は
`https://magicalmirai.com/<slug>/` の形式だが、10th のように西暦と異なる回もある。

`halls` は会場カードの詳細 (会場情報のモーダル) に出る。**公式サイトの会場表記を
そのまま写す。** ライブと企画展で使う施設が分かれている年は、その区別も
`5号館A(ライブ)・4号館(企画展)` のように残す。公式サイトが会場名しか出していない年
(2013 の横浜アリーナなど) は省略してよく、モーダルはその節を出さない。

`mapQuery` は会場情報のモーダルに埋め込む Google マップの検索語で、**普段は書かない。**
省略すると `venue` の `ja` をそのまま検索語にする。会場名だけでは目的の場所に定まらない
ときだけ書く (2014 の `東京体育館 メインアリーナ` は施設名の `東京体育館` で引く)。
検索語は常に日本語で書く。国内の会場なので、英語名より日本語表記のほうが確実に
1 か所へ定まる。

公演数は 1〜3 に限らず何公演でも書ける。`region` が `tokyo` / `osaka` 以外はすべて `other`
(黄色系) として扱われる。10th の札幌公演のように開催年をまたぐ日付もそのまま書いてよい。

## setlist.yaml

```yaml
sets:
  - performances: [osaka, tokyo] # このセットリストが適用される公演の id
    tracks:
      - order: 1
        song: カルチャ # songs.yaml のキーと完全一致させる
      - order: 3
        variants: # 日替わり / 会場別の枠
          - song: ローリンガール
            note: Day.1
          - song: ゴーストルール
            note: Day.2
      - order: 24
        song: HERO
        tags: [encore, theme-song]
      - order: 12
        song: スキキライ
        singers: [rin, len] # その年だけ歌唱者が違う場合の上書き
```

公演ごとにセットリストが大きく異なる場合 (10th の札幌公演など) は `sets` を複数書く。

### 公演回と shows

`edition.yaml` の各公演回は「日程」と「昼 or 夜」を持つ。

```yaml
shows:
  - id: day1-matinee
    date: 2025-08-09
    label: Day.1 昼
    session: matinee # matinee | evening | 省略 (区別なし)
```

`setlist.yaml` の候補には、**その曲がどの公演回で演奏されたか**を `shows` で書く。
`edition.yaml` の公演回を、公演 id・何日目・昼夜の 3 つで指す。

| キー          | 意味                                                  |
| ------------- | ----------------------------------------------------- |
| `performance` | `edition.yaml` の公演 id (`tokyo` / `osaka` など)     |
| `day`         | その公演の何日目か (1 始まり)                         |
| `session`     | `matinee` / `evening`。昼夜を分けていない年は書かない |

```yaml
- order: 2
  variants:
    - song: 初音天地開闢神話
      shows:
        - performance: sendai
          day: 2
          session: matinee
        - performance: sendai
          day: 3
          session: matinee
        - performance: osaka
          day: 1
          session: matinee
      singers: [miku]
```

この 3 つは `src/infrastructure/dataset/toCatalog.ts` で `<公演 id>/<公演回 id>` の
参照に組み立てられる。`edition.yaml` の公演回 id を `day<N>` / `day<N>-<昼夜>` で
付けているのはこのため。**id の付け方を変えるならここも直す。**

固定曲 (その公演すべてで演奏された曲) は `shows` を省略する。

**「会場替わり」「昼夜入れ替え」「日程替わり」はこの `shows` から計算される。**
データに区分を書くのではなく、演奏実績から導く。判定は `src/domain/setlist/TrackVariation.ts`。

| 表示         | 条件                                                                  |
| ------------ | --------------------------------------------------------------------- |
| 会場替わり   | 候補の分かれ方が会場の境目と一致する                                  |
| 昼夜入れ替え | 昼公演と夜公演で丸ごと入れ替わっている (会場では出し分けられていない) |
| 日程替わり   | 日の境目と一致し、会場では出し分けられていない                        |
| 両方         | 会場替わりと日程替わりの両方に当てはまる                              |
| 日替わり     | どちらでも言い表せない (A日程/B日程 が会場をまたいで不規則な年など)   |

昼夜入れ替えは日程替わりの一種だが、日付を並べるより「昼公演/夜公演」と言ったほうが
伝わるので先に切り出している。判定には `edition.yaml` の `session` が要るので、
昼夜の区別を書いていない公演回が混ざる枠は日程替わりのままになる。

`shows` が無い候補は「日替わり」になる。

### singers の調べ方

初音ミク Wiki のセットリスト表は、曲名の左の列に歌唱ボーカロイドを色で示している。
色と ID の対応は次のとおり。複数色が並んでいれば複数人での歌唱。

| Wiki の色 | ID      | ボーカロイド |
| --------- | ------- | ------------ |
| `#33ccbb` | `miku`  | 初音ミク     |
| `#ffa500` | `rin`   | 鏡音リン     |
| `#ffe211` | `len`   | 鏡音レン     |
| `#ffc0cb` | `luka`  | 巡音ルカ     |
| `#d80000` | `meiko` | MEIKO        |
| `#0000ff` | `kaito` | KAITO        |

ここから読み取れるのは**その公演での歌唱者**なので、`setlist.yaml` の枠側に書く。
原曲の歌唱者と一致するとは限らないため、`songs.yaml` には転記しない。

### 表記のきまり

- **曲名は出典の表記をそのまま使う。** 自然キーなので、勝手に記号の全角/半角を
  揺らすと他の年からの参照が壊れる (`39みゅーじっく！` と `39みゅーじっく!` は別物)。
- **作曲者名は括弧と感嘆符を半角に揃える。** 出典は `じーざす（ワンダフル☆オポチュニティ！）`
  のように全角で書くが、揃えないと統計のボカロ P 集計で同一人物が 2 人に割れる。
- **合作は `producers` に分けて入れる。** 出典の `kz(livetune)×八王子P` は
  `[kz(livetune), 八王子P]` の 2 人。統計では参加した各人に 1 曲ずつ数える。
  ただし `1640mP(164×40mP)` のように**括弧の中の `×` は別名の説明**なので割らない。
- **アポストロフィを含む曲名はダブルクォートで囲む。** `'Someday'z Coming':` は YAML として
  壊れる。`"Someday'z Coming":` と書くこと。

| ------------- | ----------------------------------------- |
| `encore`      | アンコール                                |

## songs.yaml

```yaml
'カルチャ':
  producers: [ツミキ] # 合作があるので配列。1 人でも配列で書く
  singers: [miku] # 原曲の歌唱ボーカロイド
  youtube: xxxxxxxxxxx # YouTube の動画 ID (URL ではなく ID)
  spotify: https://open.spotify.com/track/...
  appleMusic: https://music.apple.com/jp/album/...
```

`youtube` / `spotify` / `appleMusic` は省略できる。省略した場合、UI は埋め込みの代わりに
各サービスの検索リンクを出す。埋め込み再生をさせたい曲から順に ID を埋めていけばよい。

## データの出典と精度

- 公演地・日程: 公式サイト https://magicalmirai.com/
- セットリスト (2017・2018・2019・2021・10th・2023・2024・2025):
  公式サイトのアフターレポート `https://magicalmirai.com/<slug>/special_afterreport.html`
- セットリスト (2013・2014・2015・2016・2020・2026):
  初音ミク Wiki https://w.atwiki.jp/hmiku/pages/56548.html
- `theme-song` / `grand-prix` のタグ: 公式発表 (クリプトンのニュース・初音ミク公式ブログ) と
  Wikipedia の一覧 https://ja.wikipedia.org/wiki/初音ミク「マジカルミライ」
- `encore` のタグ: 公式のアフターレポート (2017〜2019) と、区切りを明記している
  ライブレポート (下記「注意点」に年ごとの URL)

公式のアフターレポートは**公演地ごと・昼夜ごとの確定したセットリスト**を持つので、
これがある年はこちらを使う。2013 と 2016 にも公式のセットリストはあるが、
ページの作りが年ごとに違うため未取り込み。それ以外の年は公式に掲載がない。

**注意点:**

- `singers` は原曲の歌唱ボーカロイドで、確実なものだけを記載している。空の曲が多い。
  公演でその年だけ別のキャラが歌った場合は `setlist.yaml` 側で上書きすること。
- 日替わり曲がどの公演のどの日だったかは、出典の記述をそのまま `note` に入れている。
  公演の `shows` と機械的に対応づけてはいない。
  ただし公演地だけを指す `note` は「大阪公演」ではなく「大阪」と地名だけにする。
  画面では短い札として出るので、「公演」まで書くと冗長になる。
- **全 14 回とも初音ミク Wiki から取り込み済み。** 曲名・作曲者・歌唱ボーカロイド・
  日替わりの条件がすべて出典どおりに入っている。
- 昼夜の区別 (`session`) は 2020 年を除く全年で埋まっている。
  2020 年だけは 3公演/日 で昼夜の区別ではないため、日付単位にしている。
- **`youtube` は「作曲者本人または公式チャンネルの投稿」だけを登録する。** 曲名が
  一致していても、転載・カバー・ゲームの録画は入れない。
  - **`〇〇 - Topic` は自動的に公式とみなさない。** YouTube が配信元の情報から
    自動生成するチャンネルで、作者自身が配信した結果できたものと、第三者が作者に
    無断で配信サービスへ登録した結果できたものが混在する。チャンネル名が作者名でも
    それだけでは根拠にならないので、曲ごとに確かめてから採ること。
    採用した例: EARTH DAY (`Tsubasa Harihara (HarryP) - Topic`)。
  - フル尺であること。本人チャンネルにあっても `#shorts` の断片は入れない。
- `youtube` は 236 曲中 211 曲に登録済み。未登録は 25 曲で、うち 23 曲は
  2024 年以前の曲。公式の投稿が見当たらないか、公式に複数版があってどれを採るか
  判断が要るもの。残り 2 曲は 2025・2026 の曲でまだ調べていない。
  未登録の曲は UI が検索リンクにフォールバックする。
- `spotify` / `appleMusic` は未登録。現状はすべて検索リンクにフォールバックしている。
- **`theme-song` / `grand-prix` は全年で埋まっている。** セットリストの出典 (公式の
  アフターレポート) がタグに当たる情報を持たないため、以前は Wiki から取り込んだ年
  (2013・2014・2015・2016・2020・2026) にしか付いていなかった。曲そのものは出典から
  正しく入っていたので、公式発表を引き直してタグだけを足してある。
  次の年に付かないのはデータの欠けではなく、事実としてその曲が無いため。
  - **2013**: テーマソングの制度がまだ無い (2014 から)。
  - **2014**: テーマソング「ネクストネスト」はライブでは演奏されず、10th で初披露された。
    タグは枠に付けるものなので、演奏していない 2014 には付かない。
  - **2016 以前**: 楽曲コンテストは 2017 開始。
  - 10th のように歴代のテーマソングを演奏する回でも、`theme-song` はその回自身の
    テーマソング (フューチャー・イヴ) にだけ付ける。
- **`encore` は全年で埋まっている。** 公式のアフターレポートは
  2017・2018・2019 だけがアンコールを区別しており (HTML の `class="encore"`)、
  それ以降の年は区別を持たない。持たない年は、区切りを明記しているライブレポートから
  補った。いずれも「本編最後の曲」がデータの 1 つ前の枠と一致することを確かめてある。
  - 2021: https://acousticspace.jp/magical-mirai-2021-setlist3/
  - 10th (東京・大阪) / 2025: https://yamamori3939.hatenablog.com/
  - 2023: https://dejiko.jugem.jp/?eid=11465
  - 2024: https://note.com/ciaozanyaw/n/n99e88cf839c1
  - 10th の札幌公演: 公演記録の E1〜E3 の区切り (リポジトリ管理者から提供)。
    初音ミク Wiki にも載っているが、Cloudflare の判定で機械的には取得できない。
- **ダブルアンコールも `encore` として扱う。** 2017 の「ハジメテノオト」が該当する。
  タグは「アンコールで演奏された枠」を示すもので、何回目のアンコールかは持たない。
